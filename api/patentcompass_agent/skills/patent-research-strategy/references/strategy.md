# 方案质量与字段

每个 directions 项的 title 和 description 表达技术组合及需要核查的问题，避免直接宣称“技术空白”“不侵权”或“领先”。basis=evidence 时，evidence 至少一条，application_id 来自当前固定分析内的真实申请，quote 连续摘自其标题或摘要；服务端会校验并计算去重支持数。

quote 优先复制与方向直接相关的原始标题，或者用 get_patent 读取完整摘要后逐字复制一段。括号、部件编号、标点和词序都必须保留，不能把相隔的句子拼接成一条引文；检索片段不足时不要补写。校验失败会指出方向、证据序号和申请号，按该提示修正对应引文再提交。

risks 与 conditions 各至少一条。缺少权利要求、法律状态、同族或商业需求时，把获取和审查它们列为推进条件，不编造对应事实。实际未完成外部检索或反例核查时维持待验证状态。

phases 至少两项，推荐证据核查、技术验证、布局评审三个阶段。每阶段给出 title、actions（字符串列表）、deliverable（具体交付物）、acceptance（可判断是否完成的条件）。阶段和负责人是建议，不能伪装成已经执行的项目记录。

允许模拟时，模拟项 evidence 必须为空，支持数由后端保持为零；方案只演示业务流程，不混入原始数量和证据。优先利用现有真实摘要提出带依据的建议，缺少完整全文并不要求改用模拟。
