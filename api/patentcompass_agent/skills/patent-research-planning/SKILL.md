# 研究规划

使用主 Agent 已取得的项目上下文；不重新猜测项目或研究 ID。

1. 提炼用户要解决的行业进入、研发立项、方向比较或布局问题，区分问答、范围调整、重新分析和报告交付。
2. `get_agent_context` 读取工作范围及研究目录；`list_datasets` 核对数据版本、质量、来源和覆盖。新项目用 `create_agent_project`，通过 `bind_agent_dataset` 绑定就绪数据。操作后重新读取上下文及 revision。
3. 从用户明确需求提取行业、目标、时间、技术范围、申请人、IPC 和来源条件。使用 `update_agent_scope` 保存/确认，提交 `expected_scope_version_id`。不能把来源中国转换为中国保护地域。类型字段不可用时说明数据缺口。
4. 完整报告需要明确研究轮次：继续现有研究或通过 `create_agent_research` 建立独立研究。新研究会建立主对话，保留当前采用报告；生成首版时按现有业务规则发布并采用。新主题不能直接覆盖旧研究。
5. 扩展同义词、中英文表达、相邻技术和可核实的分类号。检索先用核心短词，多个同义检索式用 `queries` 取并集；单式空格为 AND。仅查询得到的命中数量不能代替范围总数。

输出可执行步骤、固定范围和数据版本、需要补齐的证据。用户仅要求重新分析时停在分析成果；只有明确要求报告时进入报告技能。缺少会实质影响执行的信息才询问。

原系统的结构化路由规则保存在 [planning.md](references/planning.md)，供维护原 JSON 规划入口时读取；外部 Agent 依据主 Prompt 直接调度，不必模仿该入口输出 JSON。
