# Agent 任务修复与研究结果完善

## 业务目标

修复父任务遗漏异步子任务产物、排队重试取消遗漏子任务、原对话报告卡片重复 key；在原系统、可迁移 Skills 与 MCP 共享的业务链路中补齐候选方向、风险与阶段路线，并保留原始统计和历史报告。

## 实现

- 父 Agent 在业务工具返回和后续 `get_run` / `get_run_events` 轮询时共用子任务产物收集逻辑；同步更新分析上下文，按子任务 ID 更新活动，避免跨 worker 完成后仍判为没有产物。重复轮询不重复发送相同产物。
- 重试事务立即重绑仍未结束的子任务，覆盖新 worker 尚未开始前取消的窗口。已完成子任务保留历史归属。
- 对话按真实报告版本合并卡片，并保留尚未被活动记录覆盖的导出文件。不同版本继续独立展示。
- 新增 `patent-research-strategy` 和 `save_research_strategy`。Agent 负责建议，后端校验固定范围、版本及逐字原文，保存新分析版本，复制原统计、图表与证据；不冒充全量语义分类。候选方向、推进条件、风险、阶段行动、交付物、验收条件在工作台和报告中共用。
- 模拟方案需明确传入 `allow_mock`，与真实方案分开标识，不带真实支持证据，支持数量为零。指定研究采用真实证据，没有使用 mock 数据。
- 统计分析已有的 IPC、主体与年度数据直接展示。报告在有方案时纳入候选方向、阶段路线及可支持的地域比较；旧报告仍可修改、追加冻结路线和导出。旧统计快照中的 `data: null` 保持兼容。
- MCP 当前 40 项工具，内置 Agent 27 项工具，6 项 Skills。迁移包从源目录重新生成，无需安装到全局 Skill 目录。

长任务验收进一步发现：提交回执缺少完整检查点信息，裁剪旧批次上下文后可能重复提交。读取与提交现在共用权威进度回执，包含 `batch_status`、`completed_batches`、`next_batch_index`、已处理及总记录数；原文与已保存抽取结果仍不可覆盖。父运行同时发布原对话页面可显示的提取进度，管理接口只公开计数摘要。部署该修复时保留了原父子任务 ID，220 条既有提取记录的检查点哈希全部一致，任务经租约恢复继续处理后续批次。

任务轮询新增 `get_run(view="progress")`，省略已经持久化的检查点原文，保留状态、实际产物及批次／维度进度；默认完整视图与原 REST 读取行为保持兼容。内置宿主使用精简视图，避免轮询将所有旧抽取结果重新放入模型上下文。实际 MCP 端点已验证该视图，加载更新时既有 20 批、400 条记录的检查点哈希全部一致。

方案补全版本同时复制逐条语义归属，保留后续图表重算与分类纠正所需依据。回归先复现了方案保存后主题图表重算为空，再验证保存前后重算计数一致。

主题提交的覆盖错误回执列出遗漏、重复、未知短 ID，帮助宿主准确修正，不放宽覆盖约束。`start_semantic_analysis` 可用 `reuse_run_id` 创建主题细化任务：必须同 owner、同项目、相同范围／数据及未变化原文，来源任务必须成功；复制原批次及待复核原因，只重新提交主题，不覆盖旧任务。测试验证原复核状态保留、外部 owner 拒绝及原文改变时拒绝复用。
