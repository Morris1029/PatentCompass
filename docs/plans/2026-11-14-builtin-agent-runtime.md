# Built-in Agent Runtime Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 原系统实际对话入口使用完整主 Prompt、按需 Skills 和与 MCP 共用的工具契约，保留确认、证据、任务及版本业务。

**Architecture:** 在现有 worker 内增加可恢复的模型工具循环，加载同一 `patentcompass_agent` 包。统一工具服务提供 MCP 和内置运行层共同的输入模型、校验、分发与后端实现。旧编排保留用于已有运行恢复和兼容测试；新对话默认进入新运行层。宿主确认适配器复用原研究归属/执行授权流程，不用模型承诺替代程序校验。

**Tech Stack:** Python 3.11, Responses tool calls, Pydantic, PostgreSQL / ResearchRun / RunStep, Celery, MCP.

---

1. 增加技能目录、完整主 Prompt 和受控技能/引用读取；MCP 同样暴露加载工具。验证非法路径和内外内容一致。
2. 抽出共用工具注册与分发，MCP 和内置模型使用同一输入 Schema、错误和业务实现；保持原工具名称/参数兼容。
3. 增加内置运行层：持久化模型响应与工具进度，原确认界面继续工作，恢复不重复推理或写入；父任务取消、重试和产物引用保留。
4. 新消息入口接入运行层。模型决定技能和工具步骤，代码只执行工具和业务约束；旧有运行保留旧执行路径。
5. 从原 HTTP 消息接口进行受控集成测试，覆盖真实技能加载、分析、检索问答、报告、修改、图表和导出，以及确认/研究归属/版本冲突。原模型协议测试转为显式旧运行兼容验收，不把它们当新运行层验收。
6. 通过原前端同源对话接口及真实模型/worker 完成分析→问答→报告→修改→导出，保存实际轨迹和产物。验证主 Prompt 指纹、加载技能、共用工具调用、版本及文件；失败记录保留，不以单独 MCP 验收替代。
7. 运行后端回归、前端测试/类型检查，更新迁移包和部署文档。

## 完成与证据

- 新消息在有生成模型时默认进入 `app.agent_runtime.execute`。完整 SYSTEM_PROMPT、技能元数据、实际 SKILL.md / 引用文件参与同一个模型工具循环；明确的无模型统计功能及历史运行路径保留。
- MCP 与内置运行层共用 `tool_service` 的 Pydantic 输入契约、校验、错误与业务分发。MCP 39 项工具包含3项技能发现/读取工具；模型协议适配仅展开 Schema 引用。原研究归属和确认通过宿主 prepare_agent_action 接回原代码。
