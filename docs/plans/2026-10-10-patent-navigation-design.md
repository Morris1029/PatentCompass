# 行业专利导航报告助手设计草案

本项目面向用户选定的某个领域，完成行业范围内的专利检索、数据整理、技术与竞争分析、地理分析、可视化、候选缺口验证和导航报告编制，服务企业进入新行业前的研判、研发立项与专利布局规划。地理范围已确定为“中国范围，附全球主要布局对照”。领域作为输入项，当前不锁定具体案例；关键软件、新材料可作为后续应用方向。本项目独立建设。本次交付为设计草案，尚未接入专利库或生成实际行业报告，数据源与运行技术栈待定。

## 产品名称与课题题目

产品名称：行业专利导航报告助手。

课程题目建议：《面向行业技术态势与专利布局决策的专利导航智能体设计》。

一句话定位：以专利数据为核心，围绕选定行业绘制技术、竞争和地理布局图谱，识别经补检验证的候选机会，生成可追溯、可交互询问的导航报告。

设计特色集中在行业全景分析、技术与地域图谱、候选缺口补检，以及围绕报告继续询问和局部更新。预期价值是减少重复整理与编制工作，并提高结论的可复核程度；节约时间和判断质量需通过真实案例与人工分析对照验证。

国家知识产权局将产业规划列为专利导航的应用场景，强调以专利数据为核心融合其他数据，支撑产业竞争与技术创新决策。本方案以行业分析为基础，向企业进入、立项和布局任务提供决策依据。“中国范围”是本案例的分析范围，不表示项目具有国家级认定。[专利导航指南解读](https://www.cnipa.gov.cn/art/2020/11/24/art_66_155207.html)

## 问题与解决方向

- 行业数据整理、分析与出图耗时：通过可复用的采集、清洗、计算和制图流程完成重复工作，保留分析人员对检索范围与结论的复核。
- 检索词难以覆盖不同技术表述：先明确技术问题，扩展关键词与同义表达，并结合专利分类号组织检索。
- 找到相关专利后难以看清技术分支：结合结构化分类和语义分析整理技术主题，为每个主题保留代表专利和依据。
- 难以判断哪些方向值得进入或布局：将技术要素、解决方法与应用需求进行对照，筛选覆盖较少或尚待解决的问题，再通过针对性检索验证候选缺口。
- 少量相似专利难以支持行业判断：将统计数据集与典型案例分开，统计结果必须说明检索范围、数据来源和计数口径。
- 地图容易混淆创新主体与申请地域：分别展示申请人所在地、申请布局地和有据可核的有效保护地，标明缺失地址和法律状态信息。
- 报告容易出现有结论却缺少支撑：将关键判断关联到专利记录及具体文本，证据不足时保留待核实事项。
- 长报告阅读后难以继续分析：支持按技术分支、申请人、地区和时间追问，返回对应图表、统计依据和相关专利。

## 第一版范围

主要用户为准备进入新行业、开展研发立项或选择技术方向的企业研发人员、科研团队与产业分析人员。首个案例选定一个边界明确的产业赛道，覆盖该赛道的主要技术分支与产业环节，不限于某一企业或某项产品方案。先在一个赛道内完成行业全景分析，再向具体企业的方向选择与布局任务延伸。

中国专题数据集用于分析相关专利在中国的申请活动，包含中国和外国申请人。全球对照数据集在相同技术范围内检索，用于比较主要主体、技术分支及申请布局。中国申请人的海外布局需要根据可靠的申请人地域信息及同族记录单独分析，不能把所有 CN 文献当作中国申请人的发明。全球数据覆盖不足时，只对实际覆盖的国家、地区或申请机构进行对照。

用户选择领域后，再确定其行业边界、技术分支及纳入的产业环节。时间范围、专利类型与国际对照范围在检索前明确；最新年度单独说明公开滞后。行业分析需要在约定检索范围内尽可能完整地取得结果，不能只用向量检索的前几十条记录制作全景图。

三类场景使用同一条分析流程，报告侧重点不同：进入新行业时重点展示技术路线、发展趋势与主要申请人；立项前重点展示候选缺口、相关专利及布局建议；技术方向选择时重点对比各方向的已有方案、竞争分布和验证需求。

核心任务包括行业范围与技术分类树确认、相关专利获取、趋势与申请人分析、地理及技术可视化、候选缺口筛选及补充检索，以及长报告生成与追问。涉及产业价值、市场需求与技术可行性的建议还需产业资料和专业判断。报告提供决策依据，不据此承诺某方向一定可以获得专利，也不提供自由实施或侵权的最终判断。

## 用户输入

1. 目标行业或产业赛道，以及希望解决的进入、立项或方向选择问题。
2. 目标应用需求，可选补充已有技术方案、产品描述或参考资料。
3. 关注的国家或地区、时间范围，以及专利类型。
4. 可选的竞争对手、目标应用和检索排除条件。

设计阶段保留“某领域”作为通用输入，不要求现在确定具体行业。实际执行时，助手根据用户给出的领域提出范围说明与技术分支，用户可以调整纳入或排除的部分。检索开始前形成可查看的范围说明、技术分类树和检索式；只追问影响实际检索范围的信息。

## 领域适配

产品面向用户选择的领域运行，当前不固定具体赛道。公共流程保持一致：界定领域、建立技术分类、检索专利、清洗与分析、生成图谱、验证机会、编制报告并支持追问。各领域的术语、分类号、技术分支和评价问题在执行时确定。

关键软件或新材料仅作为可能的应用领域，不预设其专利数量、发展阶段或候选缺口。技术分类树先依据行业资料与试检索建立，再进行人工抽样校验；正式检索式中的 IPC/CPC 分类号需要查询核实后填写。

报告名称模板：《中国某领域专利导航报告——附全球主要布局对照》。设计和申请材料使用通用名称，实际生成报告时替换为用户选定领域。

## 数据来源与专利记录

专利数据源待确定。实现前需要核实可用 API 或导出文件、授权用途、字段覆盖、分页限制及更新方式。首版可先用来源明确的专利导出数据验证分析流程；接入 API 后保持相同的分析与报告流程。

专利记录至少应保留公开号、申请号、标题、摘要、申请人、申请日、公开日、申请或公开机构、分类号和来源链接。地理分析还需申请人地址或可靠的地域字段；同族及法律分析需要同族标识与定义、优先权信息、同族成员、法律事件及其来源和截至日期。关键专利深入分析需要权利要求及原文。引用关系用于网络分析时，也需保留引用来源与覆盖说明。

字段缺失需要明确标注。未提供法律状态时不推断专利有效；没有可靠同族信息时按申请或公开文献分析，并明确口径。申请人名称可以统一展示，但名称相近的不同企业不能未经核实就合并。

每次分析保存原始记录、检索式、地区与日期范围、检索时间、数据源返回总数、实际取得数量、截断或失败情况，以及清洗后的记录数量。数据源只返回部分结果时，报告应说明所覆盖的样本范围。

## 外接数据与接口

必需的是能够获取约定范围专利数据的通道，实时 API 不是前置条件。全文、同族与法律状态可以来自同一提供方，也可以按需补充，不预设每个字段都要购买独立接口。

| 能力 | 接入方式 | 使用边界 |
| --- | --- | --- |
| 专利检索与批量数据 | 授权 API、合规导出文件或授权批量数据 | 核实中国与国际覆盖、结果获取限制及字段；普通网页搜索结果不构成行业数据集 |
| 专利全文、同族与法律事件 | 主数据源附带，或按重点专利补充 | 摘要支持初步主题分析；保护范围分析需权利要求，法律状态需注明核验日期 |
| 模型与向量能力 | 模型 API 或本地部署 | 用于技术内容理解、语义召回和有依据的写作；统计数字由代码计算 |
| 产业、政策与市场资料 | 官方资料、企业披露、授权数据库或人工导入 | 对进入建议、需求和可行性提供补充依据，与专利证据分别注明来源 |
| 国家及省市边界 | 有许可的版本化地图数据文件 | 基础专题地图可以本地绘制；地图数据及边界表达需核验来源 |
| 地址定位 | 行政区字典或按需接地理编码服务 | 仅在地址未结构化、需要城市定位等情况下使用；保留无法匹配的地址 |

已核查的候选数据路径：

- 国家知识产权局系统提供检索、分析及数据下载服务，适合作为国内案例的数据获取候选。网页下载能力不等同开放 API；机器接口需另行核实。[系统介绍](https://www.cnipa.gov.cn/art/2023/2/13/art_3166_182074.html)
- EPO OPS 提供机器接口，可获取著录信息、法律事件等数据，需要注册认证并遵守使用条款。官方当前全文覆盖表未列 CN、US，不能视为全球权利要求全文库。[OPS 文档入口](https://www.epo.org/en/searching-for-patents/data/web-services/ops)、[全文覆盖说明](https://www.epo.org/en/service-support/faq/searching-patents/open-patent-services/coverage/what-coverage-full-text)
- WIPO 提供授权 PCT 数据产品和 Webservice，适合补充 PCT 数据；其产品范围不能直接替代各国专利库。PATENTSCOPE 网页的使用规则禁止自动机器人及整库批量下载。[PCT 数据产品](https://www.wipo.int/en/web/patentscope/data/index)、[网页使用说明](https://www.wipo.int/en/web/patentscope/faqs_patentscope)

首版先选一个满足字段需求的主数据通道，国际对照按覆盖情况补充，不同时建设所有供应商适配。现阶段未采购服务、未配置账号，也未验证实际返回数据。

## 分析流程

1. **需求澄清与检索规划**：明确产业赛道、决策问题、技术分支与产业环节，生成关键词、分类号和筛选条件。保留确认后的检索范围与分类树。
2. **数据采集与清洗**：获取专利记录，处理重复记录与同一申请的不同公开文献；需要时按数据源定义归并同族。规范申请人名称，记录无法归并或字段缺失的情况。
3. **专利统计与地理分析**：用确定性代码计算年度分布、主要申请人、技术分支及各类地域分布，以及有可靠数据支撑的法律状态分布。
4. **技术路线分析**：结合关键词与向量检索定位相近技术，提取已有专利试图解决的问题、技术要素、解决方法和应用场景，组织技术分支及代表专利。初步分类可依据摘要，涉及具体保护范围时需要权利要求。
5. **候选缺口发现与验证**：根据目标应用需求建立技术要素与场景的对照，寻找检索集中覆盖较少的方向或尚需解决的问题。对候选缺口扩展同义词、分类号及相邻技术检索，检查相关专利是否被遗漏，并记录验证后保留、修正或排除的理由。
6. **导航建议**：结合技术需求、现有方法和竞争分布，对候选方向给出探索价值、差异化切入点和后续验证任务。每条建议说明依据及需要补充的技术或市场验证。
7. **图表与报告编制**：从同一数据快照生成图表和章节，核查专利标识、统计口径、缺口验证记录、引用对应关系和数据范围说明。分析人员复核后形成报告版本。
8. **报告询问与局部更新**：根据用户追问筛选当前报告数据，调用统计与检索工具，返回依据。需要新增检索时说明范围变化，生成新版本，保持正文和图表一致。

向量相似度用于召回、排序和辅助主题归纳，不直接转换为创新性评分或侵权结论。仅凭某主题命中较少不能断言该领域没有专利；还需检查检索覆盖、分类划分及数据库公开情况。

用于典型案例展示的前若干条相似结果，与用于统计的数据集分开管理。全景或趋势表述必须基于明确检索口径下的数据，而非少量相似度最高的结果。统计说明应区分公开文献、申请和专利同族，年度分析说明所用日期；近期数据也要说明公开延迟可能造成的影响。

## 结论与可视化

每张图对应一个决策问题，并提供检索范围、日期口径、计数单位、缺失数据说明和可回查的记录。技术主题图中的距离表示所选模型下的语义关系，不表示创新性或商业价值。

| 决策问题 | 图表 | 可支持的判断 |
| --- | --- | --- |
| 行业专利活动如何变化 | 年度申请及同族趋势图 | 约定范围内活动变化；结合公开滞后解释近期趋势 |
| 国内主体集中在哪里 | 中国申请人省市分布图 | 主体地域集聚；申请人地址不直接代表研发或生产基地 |
| 相关技术在哪些地域布局 | 全球申请布局图、来源地与布局地流向图 | 主要申请目标及中国申请人的海外布局，不据此推断市场需求 |
| 哪些主体在哪些技术分支布局 | 申请人排行、申请人×技术分支热力图 | 主要主体及布局重点，不把数量排行等同技术实力排行 |
| 行业有哪些路线和关联 | 技术分类树、语义主题图 | 主要分支、相近方案与代表专利 |
| 技术方向随时间怎样演变 | 技术分支×年度热力图、路线演进图 | 活跃分支和时间变化；“新兴”需对应可核查的统计与文本 |
| 是否存在值得继续验证的方向 | 技术问题×解决方法×应用矩阵 | 低覆盖候选方向及补检后的判断，不直接宣布专利空白 |
| 重点布局当前处于何种状态 | 法律状态分布、重点同族清单 | 有核验依据的申请、授权及失效等状态 |
| 有哪些合作和技术关联线索 | 共同申请网络、专利引用网络（字段足够时） | 共同申请关系和引用关联，不自动认定供应链或竞争控制关系 |

地理分析分开维护三类口径：申请人所在地、申请布局地、经法律状态核验的有效保护地。最早优先权地区可作首次申请的补充视角，但不等同研发地或申请人国籍。WIPO 统计也明确区分申请人来源与申请机构。[WIPO 统计口径](https://www.wipo.int/en/web/ip-statistics/about)

同一同族在同一申请法域重复公开时，按约定单位去重；跨法域布局保留，同族总数与各地域布局数不要求简单相加相等。WO、EP 单独标注为申请路径或机构，不能直接当作有效保护国家。国内地址优先按国家、省级和城市标准化，缺失或歧义地址列为未定位；共同申请采用首申请人、全计数或分数计数中的一种明确规则。

## 文档与数据交付

目标交付是一份有深度的行业导航成果包：

1. **正式报告**：可编辑 Word 与对应 PDF，支持正文、图表、重点专利分析与证据附录。100 页以上可作为完整案例的篇幅目标，实际长度由技术分支、证据及分析深度决定，不用重复摘要填充。
2. **决策摘要**：提炼主要路线、主体、候选机会与后续行动，供企业负责人快速阅读。
3. **交互图谱**：在静态图表与可复核报告流程验证后分阶段交付，按地区、技术分支、申请人和时间筛选，点击图表回到专利清单及报告分析；与正文共享数据版本。
4. **图表及配套数据**：导出适合报告使用的图形和绘图数据，保存图名、指标、筛选规则及来源。
5. **专利数据与方法附录**：清洗后的 CSV/XLSX、原始数据快照、检索策略、分类树、主体合并与同族规则，以及字段缺失情况。数据交付遵守提供方许可。
6. **机会与验证清单**：每条候选方向关联已有布局、补检记录、支持依据、反例和下一步验证任务，作为报告附件。

WIPO 指南指出导航报告编制可能耗时且成本较高。本项目拟优先自动化整理、计算、出图及证据编排，实际节约时间与质量提升需要通过案例验证；不预设商业报价或效果。[WIPO 编制指南](https://www.wipo.int/edocs/pubdocs/en/wipo_pub_946.pdf)

## 正式报告结构

1. **摘要与决策问题**：说明主要发现、适用对象与建议行动。
2. **产业背景与技术分解**：界定赛道、产业环节、应用需求及技术分类树，注明非专利资料来源。
3. **数据范围与检索方法**：说明地区、时间、专利类型、数据源、检索式、取得数量、清洗与统计口径。
4. **总体专利态势**：呈现中国与全球对照的活动变化和主要技术分支。
5. **地理布局**：分别分析中国主体分布、全球申请布局、中国申请人海外布局及可核实的有效保护地。
6. **主要主体与竞争格局**：展示申请人、分支布局、重点同族，以及有证据的合作与关联线索。
7. **技术路线与演进**：按分支分析主要方案、发展变化、代表专利和目标技术问题。
8. **重点专利与法律状态**：结合权利要求和原文深入分析重点布局，注明核验日期及缺失信息。
9. **候选缺口与验证**：展示问题及场景矩阵、补充检索、反例和保留或排除的理由。
10. **方向与布局建议**：结合决策目标提出探索方向、合作线索、差异化问题及后续技术和市场验证任务。

附录收录专利来源、计算规则、分类与归一记录、关键文本、缺口验证过程、图表数据、数据局限和待复核问题。先完成可信数据与分析，再扩展全文篇幅。

少量数据只能形成样本分析与检索线索。数据不足时减少报告结论的范围，而不是由模型补写趋势、竞争排名或不存在的专利。

## 候选专利缺口分析

候选专利缺口指在既定技术需求与检索范围内，已有公开专利显示覆盖较少、解决路径较集中，或某项目标需求仍值得进一步探索的方向。它是待验证的布局线索；是否具有研发价值，需要结合技术可行性、应用需求和竞争情况判断。

先从相关专利中提取技术问题、技术要素、解决方法及应用场景，再结合产业资料与用户需求建立对照。对照维度不能只来自检索到的专利，否则容易忽略尚未检索到的需求。先使用层次清楚的行业技术分类树，再在各分支选取有解释意义的矩阵维度，逐层定位候选方向。

优先筛选两类线索：目标技术问题对应的公开方案较少；某类已有技术在目标应用场景或组合方式下的相关方案较少。已有成熟方案覆盖密集的方向也可以列为竞争集中区，供用户比较，但不因此认定其没有研发价值。

每条候选缺口至少说明：

1. **具体方向**：明确技术问题、应用场景或需要研究的技术组合。
2. **已有布局**：列出相关代表专利、主要解决方法和约定口径下的覆盖情况。
3. **缺口依据**：区分专利数量较少、方法集中、场景覆盖较少和需求尚待验证等不同原因。
4. **补充检索**：记录更换术语、增加分类号或检查相邻技术后的结果，以及新增结果是否改变判断。
5. **探索建议**：说明与用户目标的关系、可能的技术差异，以及技术或市场验证需求。
6. **依据充分程度**：说明数据覆盖与文本证据是否足以支持当前判断；证据不足时保留为待验证线索。

候选方向的优先顺序应由目标匹配程度、已有布局、技术可行性证据和应用需求依据共同解释，不单凭相似度或专利数量打分。技术可行性与应用需求尚无材料时，明确列为后续验证条件。

场景名称未出现在摘要中，不足以证明相关专利未覆盖该场景；仅检查摘要不足以判断保护范围。模型也不能仅凭命中较少就写成“专利空白”“可以直接申请”或“可自由实施”。

## 自研工具与人工复核

自研部分集中在专利导航的业务计算与工作流程，绘图库、文档库及地理基础库采用成熟工具，不重新实现通用软件。

| 工具 | 主要工作 | 输出 |
| --- | --- | --- |
| 检索规划与采集工具 | 关键词扩展、分类号组合、分页或文件导入、采集快照 | 范围说明、检索式与原始记录 |
| 清洗与归一工具 | 申请/公开去重、同族处理、申请人名称与地址规范化 | 可分析的数据表、归一规则和待核实项 |
| 技术分类工具 | 分类树管理、文本与语义辅助分类、代表专利定位 | 可复核的技术标签与证据 |
| 统计与地理工具 | 时间、主体、技术及地域分组，地址映射与布局流向计算 | 统计表、地图数据、缺失与异常记录 |
| 矩阵与缺口验证工具 | 生成布局矩阵、定位候选方向、补检与反例核查 | 候选机会及验证清单 |
| 制图工具 | 根据已计算的指标生成图表和交互筛选 | 图谱、报告图形及绘图数据 |
| 报告编排与校验工具 | 分章节写作、来源绑定、图文数据一致性检查 | 可编辑报告、PDF 及依据附录 |
| 报告询问工具 | 将问题转为数据筛选、统计或证据检索，按当前版本答复 | 带专利与指标依据的回答 |

例如用户追问“该技术分支的申请人主要集中在哪些省份”，助手应调用当前报告数据的申请人地址统计，再返回图表与相关主体；追问“为什么把某方向列为缺口”，则返回矩阵依据、补检记录和可能反例。新问题超出当前数据范围时发起补检并形成新版本。

人工复核保留在范围及分类树确认、申请人合并歧义、分类抽样、重点专利文本解释、候选机会与战略建议等环节。产业资料不足时列出待验证需求，不能用专利数量替代产业调查。交互询问、补检和章节更新使系统能够继续推进分析任务，而不仅是生成一次文本。

## 架构选择记录

### 单一工作流协调确定性工具与模型分析

建议首版由一个可恢复的工作流组织检索、清洗、统计、地理与技术分析、候选缺口验证、制图及报告步骤。计数、去重、地理汇总与来源标识由代码负责，模型负责技术表述理解、主题归纳、缺口假设和有依据的建议。

一次性把检索结果交给模型写完整报告，原型成本低，但难以复核统计口径和缺口依据。多个独立智能体互相协商会增加调试与合并成本。分阶段工具流程更适合当前单赛道验证，可以保留中间结果并针对候选缺口补充检索。

该选择为草案建议，具体框架待数据源和运行方式确定后再决定。方案不依赖校企项目的接口、报告运行时或部署环境。

### 分开维护统计数据与展示证据

统计面向约定范围内取得并清洗的数据集；展示证据可以从中选取相关或有代表性的记录。两者共享来源记录，但不会因展示条数限制改变统计结果。这样可以同时支持用户阅读和结果复核。

## 质量与运行要求

- 每条关键结论应能定位到专利记录和支持文本。统计结果应能用同一份数据及计算规则复现。
- 外部接口失败、分页中断和无命中分别呈现。部分结果仍可分析，但需要限制报告范围。
- 保存检索快照与分析版本，便于后续追问和局部重算。耗时步骤展示进度，模型与接口调用设置预算。
- 批量采集、文本分类和长报告按阶段分批执行，保留中间结果、失败重试与恢复位置，不要求在一次聊天响应中完成。
- 用户未公开的技术方案只发送至约定的数据源和模型服务。检索查询避免包含无关敏感内容，保留最小必要输入。
- 首版使用一个确定的主数据通道，按需补充国际对照；先验证分析流程与一个真实案例，再建设完整平台。

## 最小验证

1. **数据与统计验证**：用一个来源明确、人工核对过的技术主题数据集，验证重复记录、同一申请多个公开号、同族计数、申请人名称及缺失日期处理；自动统计与人工结果一致。
2. **检索与主题验证**：设置有人工判定的相关与不相关专利，比较关键词检索和加入语义召回后的结果，检查召回是否有帮助、主题是否得到记录支持。
3. **缺口验证**：用更换术语后能找到相关专利的案例、摘要未写明应用场景的案例和确需补充技术资料的案例，检查助手是否会补检索、修正缺口或保留不确定性。与人工审查结果对照，检查哪些候选方向有依据、哪些属于误判。
4. **地理与图表验证**：人工核对申请人地域和申请机构，检查缺失地址、共同申请、同族跨国重复以及 WO/EP 的处理；图表、正文数字与配套数据在同一筛选及口径下保持一致。
5. **报告证据验证**：核查关键专利标识与来源，逐条检查主要结论和证据是否对应；模型不得自行生成专利编号或统计数字。追问使用同一报告版本，并能复现依据。
6. **不完整结果验证**：覆盖接口失败、分页截断、字段缺失和无命中，确认报告明确范围，且不会将无结果写成无专利或可自由实施。

第一版完成标准是：一个明确产业赛道能够形成中国范围与全球对照的检索方案、可复核统计、地理及技术图表、主要主体分析、经过补检的候选机会、布局建议和证据附录，并支持有依据的追问。页数不是单独的通过标准。

## 下一阶段依赖

进入真实案例验证时，先根据用户选择的领域建立范围说明、分类树与试检索式，再核实可用数据通道及授权，用小样本检查同族、地址、日期、全文和法律事件的实际字段；随后完成可人工复核的统计、地图和缺口验证，再扩展行业数据集与完整报告。当前先完成通用设计，不以确定具体赛道为条件。运行技术栈和页面改版随后围绕已验证的数据流程确定。本次只更新设计文档，既有原型与其他文件未改动。
