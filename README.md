# PatentCompass · 行业专利导航报告助手

面向企业研发与知识产权人员、科研团队和产业分析人员，探索通过对话完成行业专利研究、技术与竞争分析、布局规划及导航报告迭代。

**当前阶段：前后端完整接入与样本验证。** `web/` 实现原型对应的真实工作区，连接 FastAPI 与持久化后台任务；支持样本导入、增量冲突确认、Word 资料、自然语言研究编排、全量语义分类、图表历史、报告编辑和指定版本 Word 导出。运行结果来自已保存的数据与成果；模型未配置时明确显示能力缺失，可继续使用统计分析。

## 后端开发

采用混合开发：FastAPI 在本地 Python 虚拟环境运行，PostgreSQL＋pgvector、Redis、Celery worker 在本项目独立 Docker Compose 环境运行。准备 Docker Desktop、Python 3.11 和 uv 后，在项目根目录运行：

```powershell
.\scripts\start-dev.ps1
```

接口文档位于 `http://127.0.0.1:8000/docs`。完整配置、兼容原有 29 个业务接口的增量扩展、启动和验收步骤见 [后端开发说明](api/README.md)。

在另一个终端运行前端：

```powershell
.\scripts\start-web.ps1
```

打开 `http://127.0.0.1:3000`，创建项目，选择或导入数据，确认范围后开始研究。前端通过同源转发调用后端，模型密钥仅存放在 `api/.env`。Node.js、pnpm 与前端校验说明见 [前端开发说明](web/README.md)。数据库、Redis、worker 使用本项目独立 Docker 容器和持久化卷；前后端代码均在本地运行。

当前数据为“无人机、中国地区筛选、部分检索结果”。申请人来源国家不代表保护地；省市、法律状态、同族与外部补检缺失时保留明确边界。候选方向是待验证的研究线索。

## 项目要解决的问题

- 专利数据整理、统计与报告编制存在大量重复工作。
- 行业技术分支、主要主体及地域布局难以放在同一口径下比较。
- 命中专利较少的方向需要补充检索与反例核查，才能形成候选布局线索。
- 报告生成后，需要继续追问、修改和保留版本，并能回查相关依据。

产品方案采用“中国范围，附全球主要布局对照”，具体领域由用户选择。完整定位、分析方法与交付目标见[产品说明](行业专利导航agent说明.md)。

## 保留的静态原型对照

| 内容 | 原型支持 |
| --- | --- |
| 项目与研究对话 | 创建项目和多次对话，同项目共享范围与研究底稿，对话消息分别保存 |
| 分析工作台 | 浏览概览、态势分析、布局与路线图、范围与目标、数据与证据 |
| 范围确认 | 从用户文字提取明确的范围信息，并支持手动调整 |
| Word 附件选择 | 选择、移除附件及展示文件信息；仅保存元数据，不上传或读取正文 |
| 图表与布局示例 | 查看技术路线、年度趋势、主体矩阵和地域分布示意图，以及示例机会、风险与行动 |
| 报告编辑体验 | 通过示例指令体验选中文字修改、引用到对话、版本差异和切回旧版 |

原型使用 HTML、CSS 和原生 JavaScript，无需构建或连接网络。项目与对话记录保存在当前浏览器的本地存储中；本地存储受浏览器和文件地址限制，不提供跨设备同步。

## 静态原型快速体验

1. 克隆仓库，或从 GitHub 下载并解压 ZIP：

   ```bash
   git clone https://github.com/Morris1029/PatentCompass.git
   ```

2. 在浏览器中打开 `front-point/prototype/index.html`。
3. 点击“新建项目”，输入研究领域与问题，体验对话和分析工作台。
4. 进入项目的“导航报告”，点击“体验报告编辑”，查看示例报告及版本交互。

页面中的“无人机自主降落”为演示主题，图表数量为模拟数据，主体使用虚构名称。真实项目的数据与报告在未生成时保持空状态。报告编辑由预设示例逻辑驱动，尚不支持模型执行任意修改要求。

## 本地验证

安装 Node.js 后，在 `front-point/prototype` 目录运行现有测试：

```bash
node --test tests/*.test.cjs
```

测试覆盖项目状态、数据迁移、报告版本及布局示例。DOM 交互测试另需可用的 `jsdom`，可通过环境变量 `PATENT_JSDOM_PATH` 指定其模块路径；未找到依赖时，该部分测试会跳过。浏览原型无需安装这些测试依赖。

## 后续范围

1. 接入经授权的外部专利数据与补检通道。
2. 补齐权利要求、法律状态、完整同族及申请人实体归一。
3. 在更完整的数据与外部证据上继续验证候选方向和地域布局。
4. 扩展 PDF 导出及正式部署所需的登录与组织权限。

上述内容属于待实现与验证目标。候选布局方向需要结合数据覆盖、补充检索和专业复核判断，不能仅凭专利数量较少认定为技术空白。
